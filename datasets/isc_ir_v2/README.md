# ISC `IR` stations: network and location from the ISC station registry

Generated by `analyze_ir_stations.py` (read-only on the dataset). Log: `analyze_ir_stations.log`. Decisions: `ir_decisions.parquet` / `ir_decisions.csv`.

Registry file: `/groups/igonin/ecastillo/UTDQuake_v2/.utdquake/isc_registry/isc_station_registry_2026-10-31.zip` (ISC `station_csv.zip`, downloaded 2026-10-31; sha256 in `SHA256SUMS`).
Rules: same site = within 10 km; epochs must overlap the station's pick time span; registry vs calculated location checked at 50 km. See the module docstring.

## Why

ISC reports picks of stations it only knows from its International Registry with the network code `IR`. ISC has no FDSN station service, so these stations had no confirmed location (0 of them) and their real FDSN network was unknown unless a same-code station of another network was found within 10 km in the same UTDQuake network. The registry (downloadable) gives every IR station's location and epochs, and lists FDSN networks too, so both can be decided from ISC's own data.

## Applying the decisions

`apply_ir_decisions.py` (its results are appended below when it runs). It applies the decisions: set `network`/location of these stations in the stations tables (`network_source = isc_registry`, `confirmed` from the registry), the `network` of their picks, recompute distance/azimuth and travel-time z-scores of the picks that gain a location, then recompute counts, validate (no pick/event rows change) and regenerate figures and totals. The decisions are kept as a persistent registry so a later extension (v2) reuses them and only decides new stations.
